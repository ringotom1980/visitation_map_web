## 發布與回復方案（供父協調，未執行）

既有 workflow 是 main push/manual → PHP syntax gate → SamKirkland FTPS 逐檔同步（60 秒 timeout），無整站發布後驗證、版本切換或自動 rollback。`dangerous-clean-slate=false` 保留遠端未追蹤檔；秘密 .env 與 docs/preview 測試排除。逐檔同步中斷可能產生新舊混用，本轮未見本專案 `.in` 殘留證據，不能照搬另一專案結論。

保留的 `deploy_root_routes.py` 不在 workflow，但對 OSError／暫時 FTP 錯誤最多重試三次，包含可能完成 rename 後的失敗。不能把它當成本輪可直接重跑的安全復原；原文件也記錄過登入前 TLS hostname mismatch。本批只改 JS，不需該根檔工具。

在既有機制下可行的核對順序：

1. 父確認本批 commit／diff 與發布授權，記錄上一版程式 manifest/hash 及可用復原版本；確認其他既有私有設定由操作者自行核對，不把它納入 UI 發布。
2. 維持原 workflow，單次發布。逾時先停止；核對失敗階段、既有同步狀態、遠端檔案 hash／殘留 inventory。未確認已完成的遠端變更前，不盲目重新觸發或清空。
3. 完成後除 workflow 狀態，逐一核對這次 JS 的完整 byte/hash 與相關頁面／資源；由具權限操作者做最少量登入 smoke，不新增正式親訪資料。靜態 hash、匿名頁、已登入流程各自記錄。
4. hash 混用或 smoke 失敗時，先確認一致復原目標，再以 revert 回到已知版本並走同樣核對。本批無 migration 回退。未確認遠端 root 路徑／TLS 時不碰 `.htaccess`。

本輪沒有改部署機制，也沒有推送、workflow dispatch、FTP 或資料庫正式寫入。
